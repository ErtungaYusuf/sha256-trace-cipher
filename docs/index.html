Technical note, October 2026

Single-Register Message Recovery in SHA-256 and a Message-Locked Encryption Scheme Built from Its Compression Function

ErtungaYusuf Source code and tests: github.com/ErtungaYusuf/sha256-trace-cipher

Abstract

We study the evolution of the internal state of the SHA-256 compression function and show that the per-round values of any single one of the eight working variables \(a, \dots, h\), together with the final digest, uniquely determine the input message. The result follows from the fact that each round computes only two new words, \(a\) and \(e\), while the remaining six are delayed copies; consequently, each message schedule word \(W_t\) can be recovered from one register by modular subtraction. We provide a reference implementation and verify recovery for all eight registers on messages of 0 to 1000 bytes. We then show that such a round trace does not constitute a ciphertext, since the digest enters only the final three rounds and the message words are recoverable without it. Finally, we describe two constructions that use no cryptographic primitive other than SHA-256: SHACAL-2 in an authenticated CBC mode, and a message-locked encryption scheme in which the key is the SHA-256 digest of the message and the ciphertext is the round trace masked by the compression function keyed through its chaining input. We discuss the underlying assumptions and the inherent limitations of message-locked encryption. The implementation is intended for study and has not been independently audited.

Keywords: SHA-256, compression function, state recovery, side-channel analysis, SHACAL-2, message-locked encryption, convergent encryption.

1Introduction

SHA-256 [1] is commonly treated as an opaque function: an input of arbitrary length is mapped to a 256-bit digest, and no efficient inversion is known. Its internal structure, however, is highly regular. The compression function maintains eight 32-bit working variables, conventionally denoted \(a\) through \(h\), and updates them over 64 rounds. This note examines what can be inferred when one of these variables is observed at every round, and whether such an observation can be turned into a meaningful encryption scheme.

The contributions are as follows.

  • We show that the per-round values of any single working variable, together with the final digest, uniquely determine the message, and we give an explicit recovery procedure for all eight variables, including multi-block messages (Section 3).
  • We show that this round trace cannot serve as a ciphertext with the digest as key, because the message words are recoverable without the digest (Section 4).
  • We describe SHACAL-2, the block cipher obtained from the compression function by removing the feed-forward, and use it in an authenticated mode built solely from SHA-256 components (Section 5).
  • We construct a message-locked encryption scheme in which the key is the SHA-256 digest of the message and the ciphertext is the round trace masked by the compression function keyed through its chaining input, and we discuss its security assumptions and inherent limitations (Section 6).

All constructions are implemented from scratch in Python without third-party cryptographic libraries. The standard modules hashlib and hmac are used only in the test suite, to validate the implementation.

2Preliminaries

2.1Notation

All words are 32 bits wide. Unless stated otherwise, \(+\) and \(-\) denote addition and subtraction modulo \(2^{32}\). The functions \(\Sigma_0, \Sigma_1, \sigma_0, \sigma_1, \mathrm{Ch}\) and \(\mathrm{Maj}\) and the round constants \(K_t\) are as defined in FIPS 180-4 [1]. We write \(S_t = (a_t, b_t, \dots, h_t)\) for the state after \(t\) rounds of the compression function, so that \(S_0\) is the chaining input.

2.2SHA-256

The message is padded with a single one bit, zero bits, and a 64-bit length field, and divided into 512-bit blocks \(M^{(1)}, \dots, M^{(N)}\). Each block is split into sixteen words \(W_0, \dots, W_{15}\) and expanded by the message schedule

$$W_t = \sigma_1(W_{t-2}) + W_{t-7} + \sigma_0(W_{t-15}) + W_{t-16}, \qquad 16 \le t \le 63. \tag{1}$$

The compression function sets \(S_0 = H^{(i-1)}\), where \(H^{(0)}\) is the standard initial value (IV), and for \(t = 0, \dots, 63\) computes

$$\begin{aligned} T_1 &= h_t + \Sigma_1(e_t) + \mathrm{Ch}(e_t, f_t, g_t) + K_t + W_t, \\ T_2 &= \Sigma_0(a_t) + \mathrm{Maj}(a_t, b_t, c_t), \end{aligned} \tag{2}$$ $$S_{t+1} = \bigl(T_1 + T_2,\; a_t,\; b_t,\; c_t,\; d_t + T_1,\; e_t,\; f_t,\; g_t\bigr). \tag{3}$$

After 64 rounds, the feed-forward yields the next chaining value, added word by word:

$$H^{(i)} = H^{(i-1)} + S_{64}. \tag{4}$$

The digest is \(H^{(N)}\).

3Message recovery from a single register

3.1Structure of the state update

Equation (3) computes only two new words per round, \(a_{t+1}\) and \(e_{t+1}\); the remaining six are shifted copies. By induction,

$$\begin{aligned} b_t &= a_{t-1}, & c_t &= a_{t-2}, & d_t &= a_{t-3}, \\ f_t &= e_{t-1}, & g_t &= e_{t-2}, & h_t &= e_{t-3}. \end{aligned} \tag{5}$$

The state is therefore fully described by the two sequences \((a_t)\) and \((e_t)\), a representation that is standard in the cryptanalysis of SHA-2 [5]. Table 1 lists the delay \(\delta\) of each working variable relative to its source sequence.

Table 1. Each working variable expressed as a delayed copy of \(a\) or \(e\).

\(d_t\)\(a_{t-3}\)3
\(e_t\)\(e_t\)0
\(f_t\)\(e_{t-1}\)1
\(g_t\)\(e_{t-2}\)2

3.2Recovering the message schedule

Proposition 1. Suppose that the state \(S_t\) is known. Then \(W_t\) is uniquely determined by \(a_{t+1}\), and equally by \(e_{t+1}\).

Proof. By (2) and (3), \(a_{t+1} = T_1 + T_2\) and \(e_{t+1} = d_t + T_1\), where \(T_2\) depends only on \(S_t\). Hence \(T_1\) is obtained from either value:

$$T_1 = a_{t+1} - \Sigma_0(a_t) - \mathrm{Maj}(a_t, b_t, c_t) \quad\text{or}\quad T_1 = e_{t+1} - d_t. \tag{6}$$

Every term of \(T_1\) other than \(W_t\) depends only on \(S_t\), so

$$W_t = T_1 - h_t - \Sigma_1(e_t) - \mathrm{Ch}(e_t, f_t, g_t) - K_t. \tag{7}$$

Since addition modulo \(2^{32}\) is a group operation, the solution is unique. ∎

Starting from the known \(S_0\), Proposition 1 is applied round by round: once \(W_t\) is determined, \(S_{t+1}\) follows from (3), and the argument proceeds to round \(t+1\). The first sixteen recovered words \(W_0, \dots, W_{15}\) constitute the message block. The remaining words \(W_{16}, \dots, W_{63}\) must satisfy (1), which provides a consistency check at no additional cost.

3.3Delayed registers and the role of the digest

If the observed variable has delay \(\delta = 0\) (that is, \(a\) or \(e\)), the procedure requires no further information. For \(\delta \in \{1, 2, 3\}\), observing the variable at rounds \(1, \dots, 64\) yields the source sequence only up to index \(64 - \delta\), and the final \(\delta\) values are missing. They follow from the feed-forward (4): since \(S_{64} = (a_{64}, a_{63}, a_{62}, a_{61}, e_{64}, e_{63}, e_{62}, e_{61})\),

$$a_{64-m} = H^{(i)}_{m} - H^{(i-1)}_{m}, \qquad e_{64-m} = H^{(i)}_{4+m} - H^{(i-1)}_{4+m}, \qquad 0 \le m \lt \delta. \tag{8}$$

For the final block, \(H^{(N)}\) is the digest. For an intermediate block, \(H^{(i)}\) is the chaining input of block \(i+1\), and the required words appear among the first \(\delta\) observed values of that block, because \(S_0^{(i+1)} = H^{(i)}\). Consequently, the digest is needed only for the last \(\delta\) rounds of the final block.

3.4Implementation and validation

encoder.py computes the digest and records the selected variable at every round; decoder.py reconstructs the message from the trace and the digest and verifies the result by recomputing the hash. The test suite (test_roundtrip.py) exercises all eight variables on messages of 0 to 1000 bytes, including lengths at padding boundaries (55, 56, 64, 65 and 120 bytes). Every recovered message equals the input, and every digest agrees with hashlib. Figure 1 reproduces the procedure for the variable \(h\).

4The round trace is not a ciphertext

A natural proposal is to treat the trace as a ciphertext and the digest as the key. Section 3.3 shows why this fails: the digest enters the recovery only through the last \(\delta \le 3\) rounds of the final block, that is, through \(W_{61}, W_{62}, W_{63}\), which are not message words. The message words \(W_0, \dots, W_{15}\) are obtained from the public IV and the trace alone. The script attack_no_key.py replaces the digest by zeros and recovers every message correctly for all eight variables (test_attack.py).

Replacing the public IV by a secret value does not remedy the problem. For the variable \(h\), the first three observed values are \(h_1 = g_0\), \(h_2 = f_0\) and \(h_3 = e_0\), which disclose half of the secret initial state directly. An adversary who knows a single plaintext can then recover the other half from \(d_t = e_{t+1} - T_1\). The trace is therefore an encoding of the message rather than an encryption: the computation involves no secret.

These observations are consistent with the literature. The invertibility of the SHA-2 round function and the description of its state by the sequences \(A_i\) and \(E_i\) are standard in collision cryptanalysis [5], and recovering \(W_t\) from leaked intermediate values is the central step of differential power analysis attacks on HMAC-SHA-2 [3, 4].

5SHACAL-2: the block cipher inside SHA-256

In the trace setting, the message schedule is the quantity to be hidden while the state is public. Reversing these roles yields a block cipher. Removing the feed-forward from the compression function gives a 256-bit block cipher \(E\) with a 512-bit key, known as SHACAL-2 [2], which was selected for the NESSIE portfolio in 2003. The key \(W_0, \dots, W_{15}\) is expanded by (1) into 64 round keys; the plaintext is the initial state \(S_0\) and the ciphertext is \(S_{64}\). The compression function is recovered as the Davies–Meyer construction \(H^{(i)} = E_{M^{(i)}}(H^{(i-1)}) + H^{(i-1)}\).

Decryption applies the inverse round, which follows directly from (2) and (3):

$$\begin{aligned} (a_t, b_t, c_t, e_t, f_t, g_t) &= (b_{t+1}, c_{t+1}, d_{t+1}, f_{t+1}, g_{t+1}, h_{t+1}), \\ T_1 &= a_{t+1} - \Sigma_0(a_t) - \mathrm{Maj}(a_t, b_t, c_t), \\ d_t &= e_{t+1} - T_1, \\ h_t &= T_1 - \Sigma_1(e_t) - \mathrm{Ch}(e_t, f_t, g_t) - K_t - W_t. \end{aligned} \tag{9}$$

The script sha256_cipher.py uses SHACAL-2 in CBC mode with a random 256-bit IV and authenticates the ciphertext with HMAC-SHA256 [9], implemented on top of the same SHA-256 code, in the encrypt-then-MAC composition. The encryption and authentication keys are derived from a random 256-bit master key. The test suite verifies that \(E_{M}(H) + H\) coincides with the compression function, that the inverse rounds invert encryption exactly, and that flipping a single plaintext bit changes on average approximately 128 of the 256 ciphertext bits, as expected of a pseudorandom permutation.

6Message-locked encryption with the digest as key

The final construction satisfies three constraints: (i) the key is the SHA-256 digest of the input string; (ii) the ciphertext is derived from the round trace of that string; and (iii) no cryptographic primitive other than SHA-256 is used.

6.1Where a secret can enter

Section 4 established that the trace can be computed forward from the public IV. Within SHA-256, the only input through which a secret can enter the computation is the chaining value. The digest is itself a chaining value: it is precisely the value that would serve as the chaining input of a subsequent block. This suggests placing the digest \(K\) in the chaining-input position of the compression function \(f\), where \(f(H, M) = E_M(H) + H\), and using its output as a keystream.

6.2Construction

Let \(s\) be the input string, optionally extended by a 16-byte random salt; let \(T = (T_1, \dots, T_{64N})\) be the trace of the variable \(h\) over all blocks; and let \(D\) be a fixed 56-byte domain-separation label. Encryption computes

$$K = \text{SHA-256}(s), \qquad M_j = f\bigl(K,\; D \,\|\, \langle j \rangle_{64}\bigr), \qquad C_t = T_t + M_t, \tag{10}$$

where \(\langle j \rangle_{64}\) is the 64-bit big-endian encoding of the counter \(j\), and the eight words of each \(M_0, M_1, \dots\) are concatenated to form the mask sequence \((M_t)\). Decryption recomputes the mask from \(K\), obtains \(T_t = C_t - M_t\), and applies the recovery procedure of Section 3. Figure 2 summarises the data flow.

6.3Integrity

Decryption accepts only if the recovered string hashes to \(K\) and its recomputed trace equals the unmasked ciphertext in every word. An adversary who modifies the ciphertext so that it decrypts to a different string \(s' \ne s\) must therefore ensure \(\text{SHA-256}(s') = \text{SHA-256}(s)\), that is, find a collision. In the test suite, flipping a single bit at any position of the ciphertext, as well as supplying an incorrect key, leads to rejection.

6.4Security argument

Without \(K\), the mask is indistinguishable from random under the assumption that the compression function is a pseudorandom function when keyed through its chaining input, the same assumption that underlies the security proofs of NMAC and HMAC [6]. The plaintext, however, depends on the key, since \(K = \text{SHA-256}(s)\), and the final trace words are related to \(K\) through (8). Such key-dependent inputs fall outside the standard pseudorandom-function model; as in the literature on message-locked encryption [8], a rigorous treatment requires the random oracle model.

6.5Inherent limitations

The construction is an instance of convergent encryption [7], formalised as message-locked encryption [8]. The following limitations stem from the defining rule that the key is the hash of the message, not from the implementation.

  1. Exhaustive search over predictable messages. If the message belongs to a small set (for example, a yes/no answer, a PIN or a date), an adversary can hash each candidate and test it as the key. The optional salt appends 16 random bytes to the string before hashing, and the key remains the digest of the string actually processed. In the test suite, an unsalted short message is recovered by trial, whereas the salted message is not. The salt is drawn from the operating system, since SHA-256 is deterministic and cannot generate randomness.
  2. Per-message keys. Each message has its own key, which must be conveyed to the recipient over a separate confidential channel.
  3. Determinism. Without salt, encryption is deterministic: identical messages produce identical ciphertexts.
  4. Length and expansion. The ciphertext reveals the message length to a granularity of 64 bytes and is four times the size of the padded message.

7Conclusion

The SHA-256 compression function computes only two new words per round, and every working variable is a delayed copy of one of them. As a consequence, the round trace of any single variable, together with the digest, determines the message, and the trace by itself provides no confidentiality. Placing a secret in the chaining-input position of the compression function, the only position at which SHA-256 admits one, yields a message-locked encryption scheme whose key is the digest and whose ciphertext is the masked trace. The scheme inherits the known limitations of message-locked encryption, most notably its vulnerability to exhaustive search over predictable messages. The implementation is intended for study, has not been independently audited, and should not be used to protect real data.

Appendix A: Reproducing the results

The implementation requires Python 3 and no external packages. On Windows, replace python with py. Program output and source comments are in Turkish.

# Section 3: single-register recovery
python encoder.py "Hello, world" -r h -o trace.json
python decoder.py trace.json

# Section 4: keyless recovery of a plain trace
python attack_no_key.py trace.json

# Section 5: SHACAL-2 with HMAC-SHA256
python sha256_cipher.py keygen -o master.key
python sha256_cipher.py enc "Secret message" -k master.key -o message.s2c
python sha256_cipher.py dec message.s2c -k master.key

# Section 6: message-locked encryption (key = digest)
python sha256_mle.py enc "Secret message" -o message.mle --key-out message.key
python sha256_mle.py enc "yes" --tuz -o message.mle --key-out message.key
python sha256_mle.py dec message.mle -k message.key

# Test suite
python test_roundtrip.py
python test_attack.py
python test_sha256_cipher.py
python test_sha256_mle.py
